# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Reproduction code for the FLAG-X paper (*FLAG-X: Hybrid machine learning workflows for automated gating of clinical flow cytometry data*). FLAG-X itself is **not** in this repo; it is the separate `flagx` package (github.com/bionetslab/FLAG-X, v0.2.1 used for the paper). This repo benchmarks FLAG-X against competing cell-type classification methods.

The repo is mid-restructure (Oct 2026). The new benchmark pipeline is being built step by step following `PLAN.md`; steps 0 (scaffolding), 1 (data curation), 2 (splits), 3 (preprocessing), 4 (method integration: wrappers, envs, runners) and 5 (shared helpers in `validation/core/`) and 6 (tuning on Imstat: runs, evaluation, best configs, effect of tuning) are done; step 7 (main benchmark): `benchmark.py` and `benchmark_eval.py` (tables) are implemented, the pilot is done (no caps needed after the SOM memory fix); final run and aggregation are next. Step 8 (training data requirements, own step since 2026-11-17): `training_data_requirements.py` implemented and smoke-tested, run pending; `training_data_requirements_eval.py` and `plot_training_data_requirements.py` implemented (2026-11-25, tested on a synthetic fixture / dummy results). Step 9 (follow-ups): `sample_order_robustness.py` implemented and smoke-tested (2026-11-25), run after the step-8 eval. The pre-revision code is frozen in `legacy/`.

- `PLAN.md`: **the authoritative plan**: general rules, the open todos per step, and the decision table (D1–D8, one line each). Read it before starting a new step. Open decisions are settled only when the step needs them; don't decide them unasked.
- `DONE.md`: append-only log of completed work per step: what was implemented, outputs, checks, findings, and the reasoning and sources behind each decision. Look up the background of earlier steps there; when a todo is finished, move its details here and leave a one-line status in `PLAN.md`.
- `config.py`: constants shared by several scripts (`ROOT`, `DATA_RAW`, `DATA_CURATED`, `DATA_SPLITS`, `RESULTS`, `FIGURES`, `SEED`, `DATASETS`, `CHANNELS`, `LOG10_CUTOFFS`, `DELTA` (margin of the paired non-inferiority / equivalence tests, steps 7 and 8), and the Plotting section `PLOT_DATASETS`, `DATASET_NAMES`, `PLOT_METHODS`, `METHOD_NAMES`, `METHOD_COLORS`, `PAGE_WIDTH`, `PAGE_HEIGHT`). `DATASETS` is the run order (curation, splits, benchmark manifest indices: don't reorder it during a run); the Plotting section sets the order, names and colors of all figures and their maximum printed size (one A4 text block: 6.3 × 9.0 in; result figures are drawn at final size with 5–8 pt fonts and included unscaled) and is used only by plot scripts. Stdlib-only and Python 3.5-compatible, since every env imports it.
- `curate_data.py` (env `fx_flagx_cpu`): raw FCS/CSV → `data/curated/<dataset>/` (`sample_<NNN>_X.npy` float32, `sample_<NNN>_y.npy` int32, `meta_samples.csv`, `meta_labels.csv`). Untransformed; compensated with flagx only if the file has a spillover matrix (BLAST110).
- `make_splits.py` (env `fx_flagx_cpu`): patient-level (stratified) k-fold splits → `data/splits/<dataset>.csv` (`split_<i>` = train/test) and `imstat_inner.csv` (`split_<i>_inner_<j>` = train/val/test, for tuning), plus `summary.csv` / `summary_inner.csv`. Same patient → same fold across lt1/lt1b/lt2/lt2b and across the BLAST110 tubes. The split CSVs are versioned; they are the single source of truth.
- `plot_dataset_overview.py` (env `fx_plot`): sample size and class balance figures → `results/dataset_overview/`, `figures/dataset_overview/`.
- `validation/core/preprocessing.py`: `Preprocessor` (transformation `log10_cutoff` / `arcsinh` / `none` + scaling `zscore` / `minmax` / `none`), numpy-only, Py3.5-compatible, fitted on the fly per task. Cut-offs in `config.LOG10_CUTOFFS`. `shared_preprocessor(dataset, arm)` builds the input arm (`shared` / `native`), `preprocessor_state(p)` the JSON record. Main benchmark default: `log10_cutoff` + no scaling (D3a/D3b); the rest only in the ablation.
- `validation/core/` (step 5): `data.py` (curated samples incl. memory-mapped loading, meta tables, splits, `outer_splits`), `sampling.py` (`downsample_indices`, `join_samples`), `seeding.py` (`derive_seed(*keys)`), `evaluation.py` (`confusion_counts` incl. abstention column, `class_counts`), `resources.py` (`track_resources` context manager: wall time, peak CPU RSS / GPU memory), `runs.py` (atomic `save_json` / `save_csv`, `run_metadata`, `n_threads`, `read_manifest`, `index_ranges`, `best_config`), `scores.py` (`f1_from_counts`: macro F1, binary datasets F1 of label 1; `class_scores`: per-class precision / recall / F1; `abstention_rate`). Same constraints as the preprocessing (numpy + stdlib, Py3.5).
- `validation/eval_helpers.py` (env `fx_plot`): helpers shared by the eval scripts (`write_csv`, `last_line`, `cap_hit`, `failure_type`); not in `validation/core/` because `cap_hit` knows method params and they are used only by the eval scripts, not inside the atoms.
- `validation/gating/`: sklearn-compatible wrappers around competing methods.
- `validation/runners/<method>.py` (step 4): per-method glue with one interface (`MODULES`, `input_arm(params)`, `build(params, seed, dataset, n_jobs)`, `fit(model, X, y, sample_ids)`, `predict(model, X, proba=False)`), imported via importlib in the method's env. Methods: `som`, `mlp`, `dgcytof`, `gatemeclass`, `lda_abdelaal`, `deepcytof`, and the sklearn baselines `rf`, `hgb`, `logreg`, `knn`, `lda_sklearn`, `gmm_mocking`.
- `tune_hyperparameters.py` (step 6; runs in every env, Py3.5): grids as constants; `manifest <array>` freezes the task list, `run <array> [index]` runs one atom (method × config × outer × inner split) → `results/tune_hyperparameters/atoms/`. One SLURM array per (env, cpu/gpu): `slurm_scripts/tune_<array>.sh` (Woody / TinyGPU, see `slurm_scripts/README.md`). Plan and atom format: `working_notes/tuning_plan.md`.
- `tune_hyperparameters_eval.py` (step 6, env `fx_plot`): tuning atoms → `results/tune_hyperparameters_eval/`: `atoms.csv` (status, resources, `cap_hit`), `failures.csv`, the aggregation chain `scores/scores_{sample,donor,inner,outer,overall}.csv` (mean / sd / n of the score, plus fit / predict runtime mean / sd; a failed atom is NaN and propagates up), the selected parameters `best_configs/params_{outer,overall}_<method>.json` (argmax mean; outer = per outer split for the Imstat benchmark, overall = consensus for all other datasets; read by step 7), and the effect of tuning `effect_of_tuning/effect_{overall,outer}.csv` + per-unit `effect_units_*.csv` (best vs. default, partial results used).
- `plot_effect_of_tuning.py` (env `fx_plot`): box plots of the per-unit Δ best − default → `figures/tune_hyperparameters_eval/effect_{outer,overall}_box.pdf`.
- `plot_benchmark.py` (step 7, env `fx_plot`; `--in` e.g. `results/benchmark_pilot_eval`, `--out`): box plots of the benchmark scores, one panel per dataset, one box per method (method colors), one point per test sample (score averaged over the seeds; macro F1, binary datasets F1 of label 1), marker = outer test fold, legend underneath → `figures/benchmark/scores_box.pdf`.
- `benchmark.py` (step 7; runs in every env, Py3.5): same structure and arrays as the tuning; atom = method × dataset × outer split × model seed (3 seeds for stochastic methods, 1 for deterministic), parameters frozen into `manifests/<array>.csv` from the best configs (Imstat per outer split, others consensus). `manifest` / `run` / `missing` / `status` / `pilot <array>` and `cap <dataset> <total>` → `results/benchmark/`: `atoms/` (JSON with status, phase, resources, metadata; rewritten after the fit and after each test sample), `counts/` (per test sample × class, incl. abstention column), `predictions/` (predicted labels per test sample, `.npz`, git-ignored). `TRAIN_DOWNSAMPLING` (per (method, dataset), off): per-sample caps set after a full-data pilot for every dataset with failures, for all methods of that dataset; such atoms get the suffix `__ds_<tag>`. SLURM: `slurm_scripts/bench_<array>.sh` (Woody: 32 cores). Plan: `working_notes/benchmark_plan.md`.
- `training_data_requirements.py` (step 8; runs in the array envs, Py3.5): atom = method × dataset × outer split × trial × n_samples × n_events (first n samples of a per-trial sample order, each downsampled to the first n events of a fixed stratified per-sample event order (`event_order`), on the fly, so nested over both axes; test samples in full; counts + resources, no predictions; params as in step 7). Execution by **lanes** (method × dataset × split × trial = one SLURM array task, `slurm_scripts/tdr_<array>.sh`, arrays `sklearn_cpu` / `flagx_cpu` / `flagx_gpu`, 4 cores): the worker (`run`) runs the atoms small → large as child processes (`atom`) with a per-atom time limit; timeout / OOM write a cutoff marker (with the atom's `n_train_events`), and every atom of the same method × dataset (any split / trial) with at least as many total training events is skipped without running (re-checked post hoc in the eval); an atom starts only if it fits into the lane's remaining time, so unfinished lanes are resubmitted (`missing`). `manifest` / `run` / `atom` / `status` / `missing` → `results/training_data_requirements/` (`atoms/`, `counts/`, `cutoffs/`, `logs/`). Methods (RF, HGB, MLP, SOM), grid, trials and time limits are constants (all fixed; 1 h per atom). The worker reads its job's time left from `squeue` (`--time-min` makes the limit vary); Woody arrays run on Gold 6326 (`icx`) only. Plan: `working_notes/training_data_requirements_plan.md`.
- `training_data_requirements_eval.py` (step 8, env `fx_plot`; `--in`, `--baseline`, `--out`): step-8 atoms + step-7 baseline (`results/benchmark_eval/scores/`) → `results/training_data_requirements_eval/`: `atoms.csv` (status incl. post-hoc budget `in_budget` / `excluded_by`), `train_class_counts/<dataset>.csv` (per-class training events per dataset × fold × trial × cell × training sample, for cells completed by any method; no method column, identical across methods (checked); input for the legacy minority count figure), `scores/<dataset>.csv` (per predicted atom × test sample, per-class scores), `sample_scores.csv` (per method × cell × test sample: per-trial scores, trial mean, step-7 baseline, d), `curves.csv` and `minimal.csv` (long, one `scope` column: `pooled` = main result, `trial_<t>` / `fold_<k>` = spread, `excl_<k>` = cross-fitted selection), `crossfit.csv`, `minimal_configs.json` (read by step 9). Cells missing in a lane (duplicates of `all` dropped by the manifest) are resolved to the atom with the same training data. Minimal cell by paired non-inferiority (lower 95 % bootstrap CI bound of mean d > −δ; δ sweep 0.001–0.1, primary `config.DELTA`), greedy (primary) and joint order, with and without the stability rule, plus the legacy criterion; bootstrap over patients (donors for Imstat), shared resamples for all cells. Plan, decisions and theory (R4.5): `working_notes/training_data_requirements_eval_plan.md`.
- `plot_training_data_requirements.py` (step 8, env `fx_plot`; `--in` e.g. `results/training_data_requirements_dummy_eval`, `--out`): figures from the step-8 eval (scope `pooled`, eligible cells only; x = training sample grid at equal spacing) → `figures/training_data_requirements/`: `delta_all_events.pdf` (main-figure candidate: mean paired Δ to the full-data model with 95 % CI, all events per sample, one line per method, one panel per dataset, −δ line, full-data scores 'All data: x | y | …' in the corner), `delta_per_events.pdf` (dataset × method grid, one line per events cap, minimal cell at `config.DELTA` (greedy) as a red ring), `delta_sensitivity.pdf` (minimal training samples (greedy) and total training events (joint) over δ), the minority count figures `minority_sensitivity.pdf` (greedy minimal training samples and the minority count of that cell over δ; minority count = smallest class count of the whole training set, all classes, 0 shown; median over the 15 lanes, band min–max) and `minority_scatter.pdf` (as legacy Fig S8 with Δ: one point per completed atom, x = minority count, y = Δ over the fold's test samples, color = training samples, descriptive Spearman r_S without p-value), and the legacy-style score figures `scores_all_events.pdf` / `scores_per_events.pdf` (kept as is; the Δ figures are the focus). Also reads `atoms.csv` and `train_class_counts/`. One y-range per figure (R4.5). Colors and formatting are finalized in one pass when all results are in.
- `sample_order_robustness.py` (step 9; runs in the array envs, Py3.5): robustness of the step-8 minimal cell to the sample order. ## Conventions for new scripts

- One script per step at the repo root, descriptive name, no numbering. Figure scripts start with `plot_`.
- Parameters are constants at the top; the docstring names the env. Paths come from `config.py`, never hard-coded.
- Each part has an `OVERWRITE` flag and skips finished outputs.
- Keep code simple and linear: one function per dataset/figure, small helpers only, no registries or frameworks.
- Don't rerun the full curation or other long jobs unasked; the user runs them manually. Smoke-test on a subset and write test output to a scratch location.

## Wrapper interface (`validation/gating/`)

Every wrapper follows the same contract. Keep new ones consistent with `dgcytof.py` / `gatemeclass.py`:
- The class subclasses `sklearn.base.BaseEstimator, ClassifierMixin`. All method hyperparameters are exposed in `__init__`.
- `predict` returns the original labels. `-1` means abstention/unassigned. Labels are mapped internally via `_process_class_labels`.
- `score` is macro F1 (abstentions get weight 0).
- `save`/`load` use pickle.
- `predict_proba` exists only where the method natively yields probabilities or votes.
- Code copied from upstream repos must be marked in comments with the URL, commit and line numbers. Changes to copied code are marked `# MOD:`. The methods are not reimplemented.

| Wrapper | Method | Env | Notes |
|---|---|---|---|

| `gatemeclass.py` (`GateMeClassClassifier`) | GateMeClass, R via rpy2 | `fx_gatemeclass` (`envs/gatemeclass.yml`) | **The env must be activated**; GateMeClass is installed from the pinned commit after creating the env (see the yml header). Known issues: `legacy/gatemeclass_bug_report.md` |
| `lda.py` (`LDAClassifier`) | Abdelaal et al. LDA, official R code via rpy2 | `fx_lda` (`envs/lda.yml`) | **The env must be activated** (`conda activate fx_lda` / `conda run -n fx_lda`). Otherwise rpy2 picks up the system R and crashes. |
| `deepcytof.py` (`DeepCyTOFClassifier`) | DeepCyTOF, Keras 1.2.2 / TF 1.0.1 | `fx_deepcytof` (Python 3.5) | must stay Python 3.5 syntax (no f-strings); CPU only |
| `acdc.py` (`ACDCClassifier`) | ACDC + PhenoGraph | `fx_acdc` (Python 3.5) | must stay Python 3.5 syntax; needs a cell-type × marker table, so it is not truly supervised; **not in the benchmark (D4)** |

The envs are mutually incompatible (Python 3.5 vs 3.12, different R/TF stacks). A benchmark must run each method in its own process/env rather than importing all wrappers together. Create an env with `conda env create -f envs/<method>.yml`. Every env includes numpy.

R-based methods get `r-base` and all R packages inside their own conda env. Never use the system R.

## Benchmark design (summary of `PLAN.md`)

- Pipeline: curated data → splits → preprocessing → shared helpers + runners → tuning (Imstat) → fit/predict (per test sample: confusion-matrix counts, optionally labels/probabilities) → scores → figures. Each step saves its outputs and the next reads them.
- Splits are generated once (group-level k-fold CV, nested inner splits for Imstat) and are the single source of truth.
- One shared transformation + normalization as the default input for all methods, applied on the fly and fitted on training data only. Deviations only by tuning (shared vs native input for DeepCyTOF; LDA-Abdelaal runs on the shared input only) or for stability (if needed), see D3. Downsampling is also on the fly, with fixed seeds.
- Package-like code goes into `validation/`. `validation/core/` (PLAN step 5) holds small, modular, stateless helpers for recurring tasks (data/split loading, downsampling of one sample, joining + shuffling samples with `sample_ids`, preprocessing, seeding, per-sample evaluation counts, wall-clock / peak CPU+GPU memory tracking). No orchestration: experiment scripts compose the helpers. Numpy-only and Python 3.5-compatible, so they run in every method env.
- Every experiment must be runnable sequentially or as a SLURM array job (task index → method × dataset × fold).

## Legacy drivers (reference)

`legacy/main.py` defines `main_<experiment>()` functions with docstrings (e.g. `main_data_processing`, `main_som_classifier`, `main_dgcytof`, `main_gatemeclass`). `legacy/run_experiments.py -m {som,dgcytof,fcnn,gatemeclass,som_parameter_tuning}` dispatches to them for the slurm jobs in `legacy/slurm_scripts/`. These scripts import `validation.*` / `flagx` from the old layout, so they will not run unchanged against the current tree.
